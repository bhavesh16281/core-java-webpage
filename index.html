Chapter 09 — Memory Areas

Heap vs Stack

This is one of the most frequently asked interview questions. Understanding it deeply separates good candidates from great ones.

🏭

Heap

Think of a warehouse — every manufactured object is stored here.

Student s = new Student();
// ↑ Student object → Heap

String name = new String("Bhavesh");
// ↑ String object → Heap
  • Stores objects and arrays
  • Shared across all threads
  • Slower access
  • Cleaned by Garbage Collector
🍽️

Stack

Think of a stack of plates — Last In, First Out (LIFO).

main() {
  test();   // test() pushed on top
}           // test() removed first

// Stack state during test():
// ┌────────┐
// │ test() │  ← top
// │ main() │
// └────────┘
  • Stores method call frames
  • Thread-specific (each thread has its own)
  • Faster access
  • Auto-removed when method returns

Chapter 12 — JVM Internals Deep Dive

What Happens When You Run java Hello?

Most developers stop at knowing the three components. But understanding what happens inside JVM step-by-step is what separates average candidates from strong ones.

01
OS Creates a New Process

When you run java Hello, the OS creates a process — just like chrome.exe or notepad.exe. Inside this process, the JVM starts up.

02
JVM Allocates Runtime Memory Areas

Before loading any code, JVM sets up its internal memory regions:

Heap Stack Method Area PC Register Native Method Stack
03
Class Loader loads Hello.class

The Class Loader locates the .class file and loads it into the Method Area of JVM memory.

04
Bytecode Verifier checks safety

Before execution, the verifier validates the bytecode: is it well-formed? Are memory accesses safe? Is the stack usage legal?

05
Execution Engine runs the bytecode

The Execution Engine (via Interpreter + JIT Compiler) translates bytecode to machine code and the CPU executes it.

Chapter 13 — All 5 Memory Areas

JVM Memory Layout

Every JVM memory area has a specific role. Interviewers often ask about all five.

Heap 🏭

Stores all objects and arrays created at runtime.

Employee e1 = new Employee();
Employee e2 = new Employee();
// Both objects → Heap
Stack 🍽️

Each thread has its own stack. Stores method call frames and local variables like emp.

Employee emp = new Employee();
// emp reference → Stack
// object itself  → Heap
Method Area 📐

Stores class metadata, field/method info, static variables, runtime constant pool. Shared across threads.

One Employee class definition → Method Area
Many Employee object instances → Heap

PC Register 📖

Like a bookmark in a book — tracks which bytecode instruction a thread is currently executing. Each thread has its own PC Register.

Stores the address of the current JVM instruction being executed by a thread.

Native Method Stack ⚙️

Used when JVM calls methods written in C or C++ (native methods). Examples: Thread.start(), System.arraycopy().

public native void start();
// "native" = outside Java
🎤 Interview Question

How many Employee class definitions exist in memory if you create 2 objects? → One (in Method Area). How many objects? → Two (in Heap).

Chapter 14 — Execution Engine

Interpreter vs JIT Compiler

This is the heart of the JVM — and the source of most advanced interview questions. The CPU understands machine code, not bytecode. The Execution Engine bridges that gap.

🔄

Interpreter

Reads and executes bytecode instruction by instruction. Simple, but slow for repeated code.

// Each loop iteration:
for(int i=0; i<1000000; i++) {
    sum += i;
}
// Interpreter re-translates
// EVERY iteration → slow
⚠️ Problem: Repeated translation
VS
⚡

JIT Compiler

Detects hot methods (frequently called), compiles them to machine code once, caches and reuses directly.

Bytecode
JIT detects "hot"
Compiled → Cache
Reused directly ⚡
✅ Solution: Compile once, reuse forever

Why Java is fast: Many beginners say "Java is interpreted." The modern, accurate answer is: Java uses both interpretation and Just-In-Time compilation. This is an excellent senior-level interview answer.

Chapter 15 — Q&A Round 2

Evaluated Answers — Internals Edition

✅ Correct What is stored in Method Area?
Answer: All class metadata, static variables, static blocks.
Interview-Grade Answer Method Area stores class metadata such as class name, method information, field information, static variables, runtime constant pool, and other class-level information.
✅ Correct What is the purpose of the PC Register?
Answer: PC register keeps track of the current execution by using counters.
Interview-Grade Answer The PC Register stores the address of the current JVM instruction being executed so that the JVM knows which instruction to execute next.
✅ Excellent Why was JIT Compiler introduced if JVM already has an Interpreter?
Answer: JIT identifies hotspots so they can be compiled to machine code, cached, and reused without re-interpreting.
Note This is already close to a senior-level answer. The key term is "hot method" — JIT monitors call frequency and only compiles methods that cross a threshold, balancing startup time vs. peak performance.
✅ All Correct Where is each part of Employee e = new Employee() stored?
Answers: a) Employee class definition → Method Area
b) Employee object → Heap
c) Variable e (reference) → Stack
Chapter 16 — Q&A Round 3

Evaluated Answers — System Thinking

At this stage, you're thinking about the JVM as a system — not just memorising definitions. Here's a careful evaluation.

✅ Correct Why does Java generate bytecode instead of machine code directly?
Answer: To make Java platform independent.
Interview-Grade Answer Java generates platform-independent bytecode so that the same compiled code can run on any operating system that has a compatible JVM. If Java generated machine code directly, a separate compilation would be required for each platform.
✅ Correct Which class loader usually loads Employee.class, Student.class, Hello.class?
Answer: Application Class Loader.
Context The Application Class Loader (also called System Class Loader) loads classes from the application's classpath — i.e., your own .class files. The three-tier hierarchy is Bootstrap → Platform (Extension) → Application.
✅ Correct When does Bytecode Verification happen?
Answer: After class loading.
More Precisely — The Linking Phases Bytecode verification is part of the Linking stage, which has three sub-steps:

❌ Incorrect When JVM calls main(), what memory structure is created immediately?
Answer given: "after class loading and bytecode is verified" — this describes the sequence, not the memory structure.
Correct Answer When JVM invokes public static void main(String[] args), a Stack Frame for main() is pushed onto the Java Stack.

✅ Correct Does JIT compile every method immediately?
Answer: False — JIT focuses on hot methods only.
Why This Matters JIT compilation has a cost — compiling takes time. Doing it for every method upfront would slow down startup. So JVM starts with the Interpreter, monitors call frequency, and only JIT-compiles methods that cross a hotness threshold. This balances fast startup time with peak runtime performance.

Chapter 18 — One of the Most Asked JVM Topics

Parent Delegation Model

This comes up surprisingly often in interviews. Understanding it shows you think about JVM security and architecture, not just definitions.

The Problem It Solves

Your app has String str = "Hello" — loaded by Bootstrap. It also has Employee emp = new Employee() — loaded by Application Loader. The question is: how do they cooperate without loading the same class multiple times, and how does Java prevent someone replacing core classes like String?

🏢 Real World Analogy

In a company, when an employee gets a task, they ask the manager first. Manager asks the director. Only if everyone above fails does the employee handle it themselves.

Director
↑ asks first
Manager
↑ asks first
Employee ← receives task
☕ JVM Class Loader Hierarchy
Bootstrap Class Loader
Loads core Java classes: String, Object, System, Thread
from rt.jar / core modules
↑ delegates to parent
Platform Class Loader
Loads Java extension / platform classes
from $JAVA_HOME/lib/ext
↑ delegates to parent
Application Class Loader
Loads your classes: Employee, Student, Hello
from application classpath

How It Works — Step by Step

1 Application Loader receives request: "Load String.class"
2 Does NOT load immediately. Asks parent: Platform Loader
3 Platform Loader asks its parent: Bootstrap Loader
4 Bootstrap says "I know String.class" and loads it ✓
5 If Bootstrap couldn't, Platform tries. If Platform can't, Application loads it itself.

Why Is This Critical for Security?

⚠️ Without Parent Delegation
java/lang/String.java (malicious) 
package java.lang;
public class String {
    // Malicious override of Java's String!
    // Could steal data, crash JVM, etc.
}

Without delegation, a rogue class could replace java.lang.String. Parent Delegation prevents this — Bootstrap always loads core classes first.

🎤 Interview Definition

Parent Delegation Model is the class loading mechanism where a class loader delegates class loading requests to its parent before attempting to load the class itself. This prevents core Java classes from being overridden by application code.
